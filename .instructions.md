# TutoApp Project Instructions for AI Assistance

## Project Context

This is a **full-stack educational platform** with a React frontend and Node.js/Express backend supporting multi-role user management (Admin, Tenant/Organization, Tutor, Student).

## Architecture Overview

### Frontend (React + Vite)
- **Location**: `Client/` directory
- **Purpose**: Web interface for all user roles
- **Key Libraries**: React Router (routing), React Query (data fetching), Tailwind CSS (styling)
- **Structure**: Components organized by user role (admin/, tenant/, tutor/, student/)
- **Authentication**: JWT-based, managed via AuthContext

### Backend (Node.js + Express)
- **Location**: `server/` directory
- **Purpose**: REST API, business logic, database operations
- **Database**: MongoDB via Mongoose
- **Key Features**: JWT auth, email notifications, file uploads, role-based access control

## Development Guidelines

### Code Organization
- **Frontend components**: Named by role (AdminHeader, TutorSidebar, StudentLayout, etc.)
- **Backend controllers**: One per feature (admin.controller.js, class.controller.js, etc.)
- **API services**: `services/` folder on both frontend and backend
- **Email templates**: `server/templates/` for transactional emails
- **Custom hooks**: Organized by role in `Client/src/hooks/`

### Key Technologies
- **Frontend**: React 19, Vite, TailwindCSS, React Router 7, React Hook Form, React Query
- **Backend**: Express, MongoDB/Mongoose, JWT (jsonwebtoken), bcryptjs for password hashing
- **Email**: Nodemailer (nodemail service configured in `config/mail.config.js`)
- **File Uploads**: Multer configured in `config/multer.js`

### User Role System
- Users have specific roles: admin, tenant, tutor, or student
- Backend validates roles via `middlewares/role.middleware.js`
- Frontend routes protected via `ProtectedRoutes.jsx` component
- Each role has dedicated layout (AdminLayout, TenantLayout, etc.)

## Common Tasks & Code Locations

| Task | Location |
|------|----------|
| Add new API endpoint | `server/routes/[feature].routes.js` |
| Implement API logic | `server/controllers/[feature].controller.js` |
| Create React page | `Client/src/pages/[role]/` |
| Add UI component | `Client/src/components/ui/` |
| Call backend API | `Client/src/services/[feature].api.js` |
| Change database schema | `server/models/[entity].model.js` |
| Add email notification | `server/templates/[event].template.js` + call in controller |
| Add custom hook | `Client/src/hooks/[role]/` |
| Database configuration | `server/configs/dbConnect.js` |

## Before Starting Development

When given a task:
1. Check if similar functionality exists (search for keywords in codebase)
2. Identify the user role(s) involved
3. Determine if backend API exists or needs creation
4. For frontend: check if UI component exists or needs building
5. For emails: check if template exists or needs creation

## Database Context

Mongoose models are in `server/models/`:
- **user.model.js**: Base user schema with authentication fields
- **admin.model.js**, **tenant.model.js**, **tutor.model.js**, **student.model.js**: Role-specific models
- **class.model.js**: Course/class definitions with instructor and students

## Authentication Workflow

1. User submits credentials to `/auth/login` or `/auth/signup`
2. Backend validates, creates JWT token
3. Token stored in client (localStorage/sessionStorage)
4. All API requests include token in Authorization header
5. Backend verifies token via `auth.middleware.js`
6. Route-level role verification via `role.middleware.js`
